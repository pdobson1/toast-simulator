# Toast Simulator MD

The toasting game as a real Sega Mega Drive ROM, written in C for the console's 68000 with no SDK: its own start-up code, a small hardware layer for the graphics chip (VDP), the controller and the sound chip (PSG), and the game.

Play it in the browser on the [play page](index.html) (EmulatorJS 4.2.3, kept in `emulator/`; on a phone it shows one big TOAST button), or load `toast.bin` into any Mega Drive emulator (BlastEm, Genesis Plus GX, Kega Fusion) or a flash cartridge on a real console.

This is the proof of concept: the kitchen, the toaster, the doneness meter, popping on time, the result words, flying toast, the plate, levels, TP and sound. Still to come from the browser version: lives and the end of a run, the shop, saving, day and night, and the cat.

## Building

Needs Ubuntu's 68000 cross-compiler and Python with Pillow:

    sudo apt install gcc-m68k-linux-gnu
    make

That writes `toast.bin`.

The art is drawn by the browser version's own code and converted to tiles. To redo it after changing the kitchen or toaster in `../index.html` (needs Node and Playwright):

    python3 tools/make_art_source.py
    node tools/render_art.js
    make

## How it fits together

- `src/boot.s`: the vector table, ROM header and start-up (TMSS, clearing RAM, copying data).
- `src/md.c`, `src/md.h`: the hardware layer: VDP set-up, tiles, name tables, palettes, sprites, the 3-button pad and PSG tones.
- `src/libc.c`: memset, memcpy and the 32-bit multiply and divide helpers. GCC's own are built for the 68020, which the 68000 can't run.
- `src/main.c`: the game.
- `src/assets.c`, `src/assets.h`: generated by `tools/build_assets.py`: the tiles, palettes and maps.
- `tools/render_art.js`: renders the kitchen, toaster and font from the browser game into `res/`.
- `tools/build_assets.py`: packs the art into four 16-colour palettes (each 8x8 tile uses one) and makes the tiles, the meter, the toast sprites and the fonts.
- `tools/check_align.py`: fails the build if the code reads or writes a word at an odd address (see below).
- `tools/fix_header.py`: pads the ROM and fills in its size and checksum.
- `tools/run_rom.py`: runs the ROM headless in the Genesis Plus GX libretro core, presses buttons, takes screenshots, records sound and reads variables. For testing.

### The screen

- Plane B: the whole kitchen, with the toaster drawn in.
- Plane A, high priority: the toaster's front, so the toast (low-priority sprites) sinks behind it; the meter and the status line.
- Sprites: the toast, the lever knob, the meter's brackets and needle, text, crumbs and sparkles.
- Palette 3 holds the toast: as it browns, two colours change every frame instead of any tiles.

### A GCC 13 gotcha

On the plain 68000, a word or long access at an odd address crashes the CPU. GCC 13 ignores `-mstrict-align` in two places: it merges byte stores into word stores (turned off with `-fno-store-merging`), and it turns `x >> 8` on a 32-bit field into a word read at an odd offset. So positions use 16.16 fixed point, and `tools/check_align.py` checks every build.
